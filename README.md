> A field guide to software across **72 industries** — what the work involves, what makes it hard, and how it plays out in India.

**Software Domains by Industry** is a self-contained, offline-friendly HTML field guide. It maps the software that exists across 72 industries — from banking and semiconductors to funeral care and space — and, for each one, explains the definition, the hard engineering problems, a typical technology stack, and how that industry's software actually looks in the Indian market.

Open any card to read a single domain in depth. There is no build step, no framework, and no network dependency: it is one HTML file you can open by double-clicking.

---

## Viewing it

- **Locally:** open `Software_Domains_by_Industry.html` in any modern browser. Everything (content, styling, images) is embedded in the file, so it works fully offline.
- **Online:** you can serve it as a live webpage with GitHub Pages — go to **Settings → Pages → Deploy from a branch → `main` / root**. The site then appears at `https://TechSathish007.github.io/software-domains-by-industry/Software_Domains_by_Industry.html`.

## Features

- **72 industry cards** across the whole economy — primary, secondary, tertiary, and public sectors.
- **Per-domain detail view** with five sections: definition, what it covers, what makes it hard, a typical stack, and India-specific examples.
- **Full-text search** across every domain, plus **sector filter chips** on the home view.
- **Light / dark theme** toggle, remembered between visits via `localStorage`.
- **Responsive layout** that works on phones, tablets and desktop.
- **Accessible by design** — skip link, ARIA labels, keyboard focus management, and reduced-motion handling.
- **SEO / sharing metadata** — Open Graph, Twitter cards, and schema.org `ItemList` structured data listing all 72 domains.
- **Zero dependencies** — no CDNs, no external fonts, no analytics, no tracking.

## How it's built

The entire project is a **single static HTML file** (`Software_Domains_by_Industry.html`, ~2.8 MB). There is no toolchain, package manager, or compile step.

- **Content** lives in one JavaScript array, `const DATA = [...]`, embedded in the page. Each entry renders a card and its detail view.
- **Rendering** is plain vanilla JavaScript — the card grid, search, filters, pager and detail view are all driven from `DATA`.
- **Styling** is hand-written CSS using custom properties for theming; light/dark is a single `data-theme` attribute on `<html>`.
- **Images** (cover photos for the most recently added domains) are embedded as base64-encoded WebP data URIs, which is what makes the file self-contained — and what accounts for most of its size.
- **Structured data** — a `<script type="application/ld+json">` `ItemList` describes all 72 domains for search engines and link previews.

Because there is nothing to build, "running" the project is just opening the file, and "deploying" it is copying one file.

### Data model

Every entry in `DATA` has the same shape, so adding a domain means adding one object:

| Field | Type | Meaning |
|-------|------|---------|
| `id` | string | URL-safe slug, also used as the anchor (`#fintech`) |
| `num` | string | Display number, `01`–`72` |
| `title` | string | Domain name |
| `tag` | string | One-line summary shown on the card |
| `def` | string | Definition — what the software actually is |
| `covers` | string[] | The sub-areas the domain spans |
| `hard` | string | What makes the engineering hard |
| `india` | string | How it plays out in India, with named examples |
| `stack` | string[] | A representative technology stack |
| `one` | string | The single thing worth remembering |
